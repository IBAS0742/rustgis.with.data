# Prompt 01 — Implement One Phase

你现在负责实现 RustGIS 轻量内网 GIS 预览改造中的一个阶段。

开始前请确认用户明确指定了阶段编号，并读取：
- `AGENTS.md`
- `docs/PRODUCT_SPEC.md`
- `docs/ARCHITECTURE.md`
- `docs/IMPLEMENTATION_PLAN.md`
- `docs/ACCEPTANCE_TESTS.md`
- Phase 0 的仓库审计报告

## 工作规则

1. 先检查 `git status`，不得覆盖已有用户修改。
2. 说明本阶段目标、当前代码入口、计划修改的文件和测试。
3. 只实现本阶段，不顺便重写其他模块。
4. 优先复用 RustGIS 现有数据结构、命令和序列化格式。
5. 新增依赖前先解释必要性，尽量避免依赖膨胀。
6. 对文件路径、项目文件、数据库元数据和 API 输入做校验。
7. 工程版本不能覆盖：后端强制拒绝已有版本 ID，不能只靠 UI 禁用保存。
8. 不可用图层必须从渲染流程排除，同时尽可能保留引用记录。
9. 大栅格不得整体读入内存；先测现有路径，再决定是否引入预处理。
10. 每个修复/行为都添加有意义的测试。
11. 运行相关测试，随后按时间和环境允许运行更广泛的 CI。
12. 检查完整 `git diff`，确认无意外修改。

## 最终报告格式

- 实现内容
- 修改文件（每个文件说明目的）
- API/数据格式变更
- 执行的命令及真实结果
- 未运行的测试和原因
- 风险/已知限制
- 下一阶段建议

如果需求与实际源码冲突，暂停该冲突部分，报告证据和最小替代方案；不要猜 API 或伪造测试结果。
