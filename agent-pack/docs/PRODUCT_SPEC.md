# 产品规格：RustGIS 轻量内网 GIS 预览

## 1. 目标

在现有 RustGIS 上做最小必要的 Web 服务端改造，提供一个单机/内网使用的 GIS 预览应用。它主要用于浏览已有本地数据、查看 PostgreSQL/PostGIS 数据，并以不可覆盖的工程版本保存地图配置。

## 2. 用户已确认的要求

### 部署与运行
- 目标部署环境：Windows、Linux、WSL、Docker。
- 主要使用方式：浏览器访问自托管 Web 应用。
- 原始数据留在运行服务可访问的本地磁盘/挂载目录或 PostgreSQL/PostGIS 中。
- 不需要用户账号、角色、多人协作、编辑冲突解决。

### 数据源
- 可在启动后配置多个目录。
- 可添加新的目录，也可以对已配置目录重新扫描。
- 重启后仍保留数据源配置。
- 目录中支持的栅格、DEM、矢量等格式尽量复用 RustGIS 当前 provider。
- 支持 PostgreSQL/PostGIS 连接；浏览器中可以浏览连接下有权限访问的数据库、schema、表和视图。
- PostgreSQL 一个服务器上的数据库彼此独立；列出多个数据库时，需要按连接逐个查询，并遵守账号权限，不得假定一个连接可以直接访问所有数据库。

### 工程
- 不需要用户概念，工程是核心组织单位。
- 支持创建、打开、复制、保存工程。
- 已保存版本不可通过应用覆盖修改。
- 需要修改时，先复制已有工程形成工作副本，再保存成新的唯一版本。
- 工程保存地图视图、图层顺序、可见性、样式和必要的图层参数。
- 工程引用原始数据；不要为了保存工程而复制大型原始数据。
- 启动后能够继续使用已配置的数据源和已保存工程。
- 文件或数据库图层不存在/不可访问时，该图层标记为不可用并且不显示在地图上。
- 尽可能保留缺失图层的引用和显示配置，便于数据恢复后重新加载；如果现有 `.rgis` 格式不能安全做到，先说明限制并提出最小兼容方案。

## 3. 最小界面

1. 数据源面板：文件夹列表、添加目录、删除目录、重新扫描。
2. 文件浏览器：显示已配置目录内的受支持文件，展示基本元数据；点击时按需打开。
3. 数据库浏览器：连接列表 -> 数据库 -> schema -> 表/视图 -> 加载图层。
4. 工程菜单：新建、打开、复制工程、保存新版本、查看版本列表。
5. 图层面板：可见性、顺序、样式等继续复用 RustGIS 现有 UI。
6. 不可用图层状态：明确标识原因，例如文件缺失、权限不足、数据库不可达、表/列不存在。

## 4. 非目标（不要主动实现）

- 用户登录、RBAC、审计审批流。
- 多人同时编辑同一个工程。
- 云端协同、在线评论、工程合并。
- 完整的企业数据目录、元数据治理或 ETL 平台。
- 自建 GIS 渲染引擎。
- 默认引入独立瓦片服务器（如 TiTiler/GeoServer）或重型消息队列。
- 自动复制/转换所有源数据。
- 默认自动把新扫描发现的文件加进当前地图。
- 将 PostgreSQL 密码写入工程文件。
- 对原始数据进行编辑；本项目优先定位为预览工具。

## 5. 性能原则

- 文件目录扫描应有界、可取消或避免阻塞地图 UI。
- 大型 TIFF/DEM 必须优先利用已有内部 overview、窗口读取或 RustGIS 已有的大栅格路径。
- 不能把 10 GB TIFF 作为普通字节数组整体读入内存。
- 如需生成预览/overview/COG 派生文件，作为可选缓存/后台任务实现，不能修改源文件；先测量现有能力再决定是否开发。
- 缓存需可重建，丢失缓存不能导致工程损坏。
- 3–20 个并发浏览者是初始测试目标，不是未经测试即可承诺的容量。

## 6. 安全边界

- 只允许访问显式配置的根目录及其子目录。
- 解析并 canonicalize 路径，防止 `..` 路径穿越；注意符号链接/junction 逃逸。
- 默认只读访问原始数据。
- 若没有认证机制，应明确服务只绑定 localhost 或可信内网地址，并提示不要直接暴露到公网。
- 工程版本创建应避免覆盖竞争：唯一 ID、原子创建/rename 或等效机制。
- 错误消息和日志不应泄漏数据库密码或敏感连接串。
